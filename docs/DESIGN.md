# Duet-Translator · 对读 设计文档

左右分屏同时显示「原网页」和「翻译后的网页」，两侧按段落对齐同步滚动；翻译引擎可接自部署模型或任意翻译 API。目标浏览器为 Edge（Chromium，Manifest V3），Chrome 同样可用。

---

## 1. 交互

| 操作 | 行为 |
|---|---|
| 首次安装 | 自动打开引导页：固定图标 → 选引擎填 Key（可测试）→ 一键打开示例页并开启对读；目标语言默认跟随浏览器语言 |
| 点工具栏图标 | 弹窗：开关分屏；选引擎、填 API Key / 地址 / 模型、测试连接（自动保存，已打开的分屏立即生效） |
| `Alt+Shift+Y`（Mac `⌥⇧Y`） | 当前标签页进入 / 退出分屏 |
| 右键「对读：从这里开始」 | 进入分屏，并定位到右键处的段落 |
| 滚动任意一侧 | 另一侧跟随，焦点线处的段落对齐 |
| 鼠标悬停段落 | 两侧同一段落同时高亮（蓝框 / 黄底） |
| 顶栏 | 目标语言、引擎切换、同步开关、高亮开关、「全文」、交换左右、设置、关闭 |
| 分隔条 | 拖动调整左右比例 |
| 关闭分屏 | 原页面停在左窗格当前正在读的段落 |
| 在任一侧点链接 | 另一侧跟随到同一页面，地址栏同步（同源时） |

## 2. 总体架构

```
┌──────────────────────── 当前标签页（顶层文档，原页面被隐藏） ────────────────────────┐
│ shell.js（外壳 + 同步协调器，shadow DOM 顶栏）                                       │
│   ┌──────── iframe L（原文） ────────┐  ┌──────── iframe R（译文） ────────┐          │
│   │ pane.js：切段落 / 锚点 / 滚动上报 │  │ pane.js：同上 + 按需翻译与回填    │          │
│   └──────────────▲───────────────────┘  └──────────────▲───────────────────┘          │
│                  └──── postMessage(token) ────────────┘                               │
└──────────────────────────────────────┬───────────────────────────────────────────────┘
                                       │ chrome.runtime 消息
┌──────────────────────────────────────▼───────────────────────────────────────────────┐
│ sw.js（Service Worker）：注入脚本 · DNR 规则 · 翻译调度（缓存→分块→限流→provider）   │
│   providers.js：openai 兼容 / deepl / mock     cache.js：IndexedDB 译文缓存           │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

| 文件 | 运行位置 | 职责 |
|---|---|---|
| `content/bootstrap.js` | 所有页面所有 frame（静态注入，极小） | 识别自己是不是分屏窗格（`window.name` 带标记），是则请 SW 注入 `pane.js`；顶层记录右键目标 |
| `content/shell.js` | 顶层 frame（点按钮时注入） | 搭建分屏 UI、两个 iframe；收集两侧锚点与滚动状态，决定谁是驱动方、算跟随方位置；导航跟随 |
| `content/pane.js` | 两个 iframe 内 | 滚动容器识别、段落切分、锚点上报、滚动原因判定、悬停高亮；R 侧负责按需翻译 |
| `shared/sync-core.js` | 纯函数（可在 node 单测） | 锚点配对 + LIS 去噪、分段线性映射、焦点线公式 |
| `shared/segment.js` | DOM | 段落切分、key、行内结构序列化（占位标签）与回填 |
| `background/sw.js` | Service Worker | 注入、DNR、翻译请求的缓存/分块/并发/取消 |
| `background/providers.js` | Service Worker | 引擎适配：OpenAI 兼容、DeepL、Mock |
| `popup/` | 工具栏弹窗 | 开关分屏、快速设置引擎与 Key、中英切换；`options/` 为完整设置页 |
| `shared/i18n.js` | 各处共用 | 界面中英文字符串；设置 `uiLang`（auto / zh / en）决定，切换后弹窗、设置页、已打开分屏的顶栏、右键菜单、错误信息立即生效。插件名称与描述在 `_locales/`，跟随浏览器语言 |

没有构建步骤：全部是经典脚本，直接「加载解压缩的扩展」即可。

## 3. 为什么用「同源双 iframe」

在当前标签页上盖一层全屏 UI，里面放两个 iframe，都加载当前 URL。

| 方案 | 问题 |
|---|---|
| 克隆 DOM 做右侧 | CSS-in-JS 用 `insertRule` 注入的样式不在 DOM 里，克隆后样式丢失；页面 JS 不运行，懒加载图片、交互失效 |
| 阅读模式（抽正文） | 丢掉原网页外观，用户要的是"当前网页"本身 |
| 两个浏览器窗口 | 不是一个标签页，体验割裂 |
| 扩展页面里放两个 iframe | iframe 跨源：`X-Frame-Options: SAMEORIGIN` 会拦截，cookie 变成第三方（登录态丢失），地址栏显示扩展 URL |
| **顶层同源双 iframe（采用）** | 顶层就是该网站本身，所以 SAMEORIGIN 天然放行、cookie 是第一方、地址栏不变；每个窗格有真实的半宽视口，响应式布局正确 |

补充措施：

- `X-Frame-Options: DENY` / `frame-ancestors 'none'` 的网站：分屏期间 SW 为**该标签页的子框架**加一条 DNR 会话规则移除这两个响应头，关闭分屏或关闭标签页即删除。可在设置里关掉。
- iframe 加 `sandbox`（不含 `allow-top-navigation`），页面的防嵌套脚本无法把整个标签页跳走。
- 代价：页面会被加载两次（左右各一次）；带状态的页面（POST 结果页、购物车）两侧可能不同。

## 4. 段落切分与 key（两侧对齐的基础）

`segment.js` 把 DOM 切成「翻译单元」：

- **element**：只含行内内容的块元素（`p/li/h1/td/…`，或只含文字的 `div`）。
- **run**：混排容器里夹在块元素之间的一串行内节点，例如 HN 评论 `文字<p>…</p>`。不包裹、不改 DOM，位置用 `Range` 量。
- **mark**：`pre/video/canvas`，不翻译，只当对齐锚点（代码块在两侧等高，是很好的锚点）。
- 跳过 `script/style/code/pre/textarea/svg/[translate=no]/.notranslate/contenteditable`。
- `<a><div>…</div></a>` 这类"行内元素包块元素"按块容器处理。

**key = hash(规范化原文) + "." + 该哈希在本页的出现序号。** 两个窗格加载同一页面、用同一算法切分，同一段落的 key 必然相同。R 侧翻译后 key 不变（key 记在单元对象上，状态都放在 WeakMap，不往原文 DOM 写属性）。

## 5. 滚动同步

### 5.1 锚点与映射

每个窗格把单元的上下边界换算到「滚动内容坐标」上报：`{k, t, b, n}`（n 为文字长度）。shell 做：

1. **配对**：同 key 的单元给出两个点 `(tL, tR)`、`(bL, bR)`。上下边界都用，所以段落内部也按比例对齐（译文段落比原文高 2 倍时，读到原文段落一半，译文也在一半）。
2. **去掉并排元素**：叶子段落在正常文档流里不会在竖直方向重叠；一旦重叠，就是并排的（浮动图注、信息框行、侧栏短项挨着正文，表格同一行的单元格，多栏卡片）。它们的锚点会插进正文段落内部或跨在两段之间，把正文的段内插值带偏。每组重叠只保留文字最多的一段（相同则更高）。这一步让维基百科这类图文混排页面的对齐误差从几十到几百 px 降到 0（见 COMPAT.md）。
3. **去噪**：按左坐标排序后，对右坐标取**最长严格递增子序列（LIS）**。固定/吸顶元素、两侧动态内容不一致造成的乱序点会被剔除。
4. 加上端点 `(0,0)`、`(HL,HR)`，得到单调分段线性映射 `LtoR / RtoL`。

### 5.2 焦点线

不直接映射 `scrollTop`（那样只有视口顶端对齐，底部会对不齐、两侧也不会同时到底），而是用一条随滚动进度移动的「焦点线」：

```
进度 r = t / (H - vh)
焦点线 p = t + r · vh          // 页顶时在视口顶部，页底时在视口底部
q = map(p)                     // 映射到另一侧
t' = q · (H' - vh') / H'       // 解 t' + (t'/(H'-vh'))·vh' = q
```

结果：两侧同时到顶、同时到底；中间任意位置，焦点线所在的那一段两侧精确对齐。

### 5.3 谁是驱动方（防止两侧互相拉扯）

两侧都会产生 scroll 事件，必须分清"用户滚的"和"被程序带着滚的"。窗格对每个 scroll 事件判定原因：

| 原因 | 判定 | shell 的处理 |
|---|---|---|
| `prog` | 位置等于 shell 刚下发的目标（目标越界时与截断值比较） | 忽略 |
| `user` | 700ms 内有 wheel/键盘/触摸/指针输入 | 仅当本侧"最近一次输入"比当前驱动方更新时，才夺取驱动权 |
| `layout` | 700ms 内发生布局变化（译文插入、图片加载引起的滚动锚定跳动） | 跟随方被拉回对齐位置；驱动方不动 |
| `other` | 都不是（如浏览器查找跳转） | 本侧成为驱动方 |

`prog` 优先于 `user` 判定，否则两侧都"刚有过输入"时会互抢驱动权（测试里抓到过这个 bug）。

### 5.4 其他细节

- **内部滚动容器**：window 不可滚时，找面积最大、`overflow-y: auto|scroll` 的元素作为主滚动容器（文档站、SPA 常见）。
- 锚点在布局变化时节流重算（ResizeObserver + MutationObserver + 1.5s 兜底），签名不变不重复上报。
- 打开分屏时左窗格定位到用户原来正在读的段落；关闭时原页面回到左窗格当前段落。

## 6. 翻译管线

### 6.1 保留行内格式：占位标签

```
<p>See <a href="…">this reference</a> and the <code>&lt;p&gt;</code> element.</p>
→ "See <g1>this reference</g1> and the <x2/> element."
```

- `<gN>…</gN>`：可翻译的行内元素（链接、加粗…）；回填时**复用原元素对象**，SPA 链接的事件监听不丢。
- `<xN/>`：原子节点（图片、`code`、`br`、图标），原样放回。
- 只包了一层的外壳会被剥掉（`<li><a>Home</a></li>` 直接翻 `Home`），减少标签。
- 回填时校验标签嵌套；模型弄乱标签就降级为纯文本，原子节点补在末尾，保证内容不丢。
- DeepL 用 `tag_handling=xml` 原生支持这种标签；LLM 在 prompt 里约束。

### 6.2 LLM 批量协议（OpenAI 兼容）

- system prompt 规定：输入是 JSON 字符串数组，输出同长度、同顺序的 JSON 数组；保留标签；已是目标语言的原样返回。
- 解析容错：去掉 `<think>…</think>`、```json 代码块包裹；条数不对或 JSON 坏了 → **二分重试**，最终退化为逐条翻译。
- 429 / 5xx / 网络错误指数退避重试 3 次；被取消的请求不重试。
- `extraBody` 原样合并进请求体，用于各家特有参数（如关闭推理）。

### 6.2.1 流式回填

- OpenAI 兼容引擎默认 `stream: true`（SSE）。SW 边收边用一个**增量 JSON 数组解析器**扫描模型输出：跳过 `<think>…</think>` 与代码块前缀，按"顶层逗号数"确定下标，每闭合一个字符串元素就通过 `chrome.tabs.sendMessage(tabId, …, {frameId})` 立刻推给发起请求的窗格；缓存命中的段落也立刻推送。
- 窗格收到即回填该段；整批结束时用最终结果对账（模型条数不对时会二分重试，已流式显示的段落以最终结果为准）。
- 服务端不支持流式（返回普通 JSON）时自动退回非流式；流式下超时按"多久没收到新数据"计算。
- "正在翻译"提示：在途段落用 Web Animations 做透明度呼吸（不改页面属性/样式，不受页面 CSP 影响），回填或取消时清除；顶栏有请求中转圈。
- 预取窗口跟随滚动方向：往下读多翻下方，往回翻多翻上方。

### 6.3 缓存

IndexedDB，key = `sha1(引擎类型|引擎id|模型|源语言|目标语言|原文)`。回滚到看过的位置、重开同一页面、换回之前的模型，都不再请求。超过 6 万条按时间淘汰。

## 7. 按需翻译与成本控制

默认**只翻译看得见的部分，滚到哪翻到哪**：

| 机制 | 说明 |
|---|---|
| 翻译窗口 | 视口上方 0.25 屏 + 视口 + 下方 `prefetchScreens` 屏（默认 0.5；设 0 只翻可见区） |
| 滚动中不请求 | 停止滚动 300ms 后才翻译当前位置；快速划过的内容一律不翻 |
| 取消在途请求 | 停下时，整批段落都已远离阅读区（上 1.5 屏 / 下 2.5 屏之外）的请求被中止（服务端停止生成，省输出 token）；这些段落回到待翻译状态，滚回来再翻 |
| 不发送 | 隐藏元素（`checkVisibility`、折叠菜单、语言列表）、已是目标语言的段落（就近 `lang` 属性，或中日韩俄阿等文字脚本判断）、缓存命中 |
| 固定元素 | 导航栏、吸顶目录只翻当前可见的，且排在正文之后，不抢请求队列 |
| 并发均分 | 窗口内文字按空闲并发槽均分成几批并行发出，首屏更快 |
| 全文 | 只有点「全文」才翻整页，并先弹框告知剩余段数与字符数 |
| 透明 | 顶栏显示「本页已请求 N 字符」（只计缓存未命中、实际发出的部分） |

实测（`test/e2e/run.mjs` 第 5 组）：打开后快速一路划到底部再停下，78 段的演示页只发送了 26 段，首屏在途的 3 个请求被取消，划过的中段 0 段被翻译；滚回顶部后首屏重新翻译。

真实网站实测（DeepSeek V4.1 Flash，英文维基百科 Typography 条目，可见 275 段）：连续停 4 次、每次下滑 900px，共请求约 1.16 万字符。

| DeepSeek 参数 | 首屏出现译文 | 每次停下后当前屏翻完 |
|---|---|---|
| `{"thinking":{"type":"disabled"}}`（预设） | 1.9s | 2.5–5.5s |
| `{"reasoning_effort":"low"}` | 3.6s | 5–7.6s，偶有 >20s |

翻译不需要推理；关闭后单段延迟 5.1s→1.9s，输出 token 411→68。

## 8. 接入引擎

统一接口：`translate(segments: string[], cfg, ctx) → Promise<string[]>`，`ctx = {from, to, page, signal}`。

| 类型 | 适用 | 关键配置 |
|---|---|---|
| `openai` | vLLM、SGLang、Ollama（`http://host:11434/v1`）、LM Studio、llama.cpp server、DeepSeek、通义（DashScope 兼容模式）、OpenRouter… | `baseUrl`（到 `/v1` 为止；DeepSeek 为 `https://api.deepseek.com`）、`model`、`apiKey`、`temperature`（留空不发送）、`extraBody`、`systemPrompt`、`batchChars/batchSize/concurrency/timeoutMs` |
| `deepl` | DeepL API Free / Pro | `endpoint`、`apiKey`（未用真实 key 实测） |
| `mock` | 离线演示 / 测试 | `latencyMs` |

常用 `extraBody`：

- DeepSeek V4.1 Flash：`{"thinking": {"type": "disabled"}}`
- vLLM / SGLang 上的 Qwen3：`{"chat_template_kwargs": {"enable_thinking": false}}`

新增引擎：在 `providers.js` 的 `PT.providers` 上加 `{label, translate}`，在 `options.js` 的 `FIELDS` 里声明表单字段即可。自部署模型在远程 GPU 机器上时，让 Edge 能访问到它的地址即可（例如在 Windows 上 `ssh -L 8000:localhost:8000 gpu-host`，`baseUrl` 填 `http://127.0.0.1:8000/v1`）。

## 9. 权限与安全

- `host_permissions: <all_urls>`：要往任意网站的 iframe 注入窗格脚本，SW 也要能直连任意引擎地址（不受 CORS 限制）。
- API Key 存在 `chrome.storage.local`（不走 `storage.sync`，不会同步到云端），只在 SW 中使用，不进入网页上下文。
- DNR 规则只作用于**分屏中的那个标签页的子框架**，关闭即删；它会让窗格页面失去 CSP 保护，可在设置中关闭（关闭后禁止嵌入的网站无法分屏）。
- 窗格与外壳之间的 postMessage 带随机 token 并校验来源 frame；传的只有滚动位置和段落 key，不含 API Key，翻译请求也不走这条通道。

## 10. 已知限制与后续

| 项 | 现状 / 计划 |
|---|---|
| Cookie 同意弹窗 | 两侧是分别加载的页面，需要各点一次 |
| 反爬虫验证 | Cloudflare 等质询页可能拒绝在 iframe 中通过；详见 COMPAT.md |
| 句子级对齐与配色 | 现在是段落级。可让模型返回句子对应关系，做 Paralate 那样的句子着色 |
| Shadow DOM 内的文字 | 不切分（Web Components 内部内容不会翻译） |
| 页面加载两次 | 广告、随机内容、A/B 实验可能两侧不同；LIS 会剔除对不上的锚点，但该部分不会有译文对应 |
| 跨源导航 | 两侧能跟随，但地址栏只能在同源时同步；关闭分屏时会跳到窗格当前 URL |
| 繁简转换 | 目标为简体时，带脚本判断会把繁体中文视为"已是中文"而跳过 |
| PDF、`edge://` 页面、扩展商店 | 浏览器不允许注入 |
